## P0 — breaks the operator flow

### P0-1 · The only finished demo can never be approved or sent
**Page:** Вхідні + business card → Кампанії
**Saw:** `Pagoulatos luxury hair salon` is `site_ready`, `site_projects.state='deployed'`,
demo live and good at `http://localhost:8788/6k9wx41i5nbl4aq82k1o45nx/`. Its card shows
the primary green CTA **«Підтвердити відправку →»**. Clicking it lands on
`/inbox?business=gr-patras-pagoulatos-luxury-hair-salon` which renders
**«Для цього бізнесу нічого не чекає.»**
**Expected:** an approval card with the message draft, channel and Approve/Reject.
**Root cause:** the `approvals` table is **empty (0 rows)**. Job #589 `request-approval`
for this business ended `needs_human` on 2026-08-16 with
`AgentSchemaError: agent "outreach-writer" produced no schema-valid output after 3 attempts`.
No approval row → `loadApprovalQueue()` returns nothing → the inbox has nothing to show.
The job is also older than the 3-day inbox window (`JOB_INBOX_WINDOW_MS`,
`ui/lib/inbox.ts:118`), so the failure is invisible there too.
**Why P0:** the entire product converges on this one action. The single demo the factory
ever finished is unreachable, and the failure that caused it is silent. The Telegram
"демо готове" notification (`uiLinks.approvalQueue`, `src/telegram/notify.ts:63`) leads to
the same dead end.
**Evidence:** `docs/audit/shots/04-pagoulatos-card.png`, `docs/audit/shots/05-inbox-deadend.png`
```sql

select id,status,error_detail from workflow_jobs where job_type='request-approval';
-- 589 | needs_human | AgentSchemaError: agent "outreach-writer" produced no schema-valid output…
```

- **P2-6** Latent hydration mismatch: `ui/components/SettingsGroupForm.tsx:119` calls
  `new Date(field.updatedAt).toLocaleString('uk-UA')` in the render body of a client
  component — the exact pattern `lib/format.ts:37-42` documents as forbidden. Does not fire
  today only because the UI container's `TZ=Europe/Athens` matches the test browser; it will
  fire from a phone in another timezone.
- **P2-7** `ui/lib/humanStatus.ts` PROJECT map lacks `cancelled`, so a cancelled build
  renders the raw English word. One such row exists (`site_projects` id 5, TRENDY HAIR).
- **P2-8** ~~`OtherActionsDialog.tsx:27` offers stage `deploy-demo` and `stageNames.ts` carries
  `normalize`, `send-outreach`, `send-followup`, `poll-replies` — none are real `job_type`
  values, so the operator can enqueue a job nothing consumes.~~
  **FALSE POSITIVE — retracted 2026-08-20 (e2e gate work).** All five ARE real job types.
  They are members of the `JobName` union (`ui/lib/queue.ts`) and every one of them has a
  registered handler in `HANDLERS` (`src/workers/main.ts`): `normalize → normalizeHandler`,
  `deploy-demo → deployHandler`, `send-outreach → sendOutreachHandler`,
  `send-followup → sendFollowupHandler`, `poll-replies → pollRepliesHandler`. `HANDLERS` is
  typed `Record<JobName, …>`, so a name that was not a real job type would fail typecheck.
  Nothing enqueued from this dialog goes unconsumed. Row kept rather than deleted so the
  claim is not re-derived from the same reading later; `pnpm e2e` now asserts every
  `stageNames.ts` key and every `OtherActionsDialog` stage is a registered handler.
- **P2-9** Contact channel (`whatsapp`, `telegram`) and outreach message `state`
  (`manual_pending`, `simulated`) render raw in the Контакти and Розмова tabs.
- **P2-10** Console shows no JS errors on any page — only a11y warnings: form fields without
  `id`/`name` (×3), incorrect `<label for>` (×10), password field outside a form.
  **Amended 2026-08-20 (e2e gate):** there IS one intermittent JS error, missed here because
  it fires roughly 1 load in 6. `/settings/system` throws React #418 (hydration text
  mismatch). Cause: `loadHeartbeats()` (`ui/lib/settings.ts`) renders a wall-clock label for
  each worker heartbeat, and workers re-stamp every 30 s; the page is `force-dynamic`, so the
  HTML render and the hydration render are two separate reads of that value and a heartbeat
  landing between them changes the text. Not a formatting bug — `beatLabel` already formats
  server-side, which is what P2-6 asked for — but a live-value bug: the fix is to render the
  heartbeat's own timestamp rather than a value derived from "now". Harmless today (React
  re-renders the subtree) and left unfixed pending a display decision. `pnpm e2e` retries a
  console error once and fails only on a reproducible one, so this does not make the gate flap.
- **P2-11** Facts truncated mid-sentence with `… (text truncated in captured source)` and a
  mojibake byte (`αγάπ�`) surfaced verbatim to the operator.
